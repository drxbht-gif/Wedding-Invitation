SIMMI & DHEERAJ WEDDING GUESTBOOK — FREE BACKEND SETUP

The website now includes a shared guestbook interface for text wishes and voice greetings. To make submissions visible across all visitors, connect it to a free Supabase project.

1) Create a free project at https://supabase.com/
2) In Project Settings / API, copy the Project URL and the publishable key (or legacy anon key).
3) In index.html, replace:
   PASTE_YOUR_SUPABASE_PROJECT_URL_HERE
   PASTE_YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY_HERE
   Never use the service_role or secret key in public HTML.
4) Open Supabase SQL Editor and run the SQL below.
5) In Supabase Storage, create a PUBLIC bucket named wedding-greetings. For this starter setup, public bucket media is viewable by anyone with the link; do not use it for private content.
6) Upload the updated index.html and assets folder to GitHub Pages. Test from a second phone/browser.

SQL (paste into Supabase SQL Editor):

create table if not exists public.wedding_guestbook (
  id bigint generated by default as identity primary key,
  name text not null check (char_length(name) between 1 and 80),
  message text not null default '' check (char_length(message) <= 1500),
  entry_type text not null check (entry_type in ('comment','audio','video')),
  media_path text,
  media_type text,
  approved boolean not null default false,
  created_at timestamptz not null default now()
);

alter table public.wedding_guestbook enable row level security;

create policy "Anyone can read approved guestbook entries"
on public.wedding_guestbook for select
to anon, authenticated
using (approved = true);

create policy "Visitors can submit guestbook entries for moderation"
on public.wedding_guestbook for insert
to anon, authenticated
with check (
  approved = false
  and char_length(name) between 1 and 80
  and char_length(message) <= 1500
  and entry_type in ('comment','audio','video')
);

-- Storage bucket policies: create bucket wedding-greetings in Storage and set it PUBLIC.
-- Allow visitor uploads into the bucket (unapproved audio is not shown on the website until
-- a matching approved database row is created, but a public bucket means URLs may be guessable).
create policy "Visitors can upload wedding greetings"
on storage.objects for insert
to anon, authenticated
with check (bucket_id = 'wedding-greetings');

MODERATION:
Every submission is initially approved=false, so it will NOT show publicly until approved.
In Supabase Table Editor -> wedding_guestbook, review submissions and change approved to true.
To reject a submission, delete its row and delete its associated object from Storage.
Do not make an approval/update policy available to anonymous visitors. Approve from the Supabase dashboard.

IMPORTANT LIMITATIONS / SAFETY:
- This is a practical starter, not a full anti-spam system. Public forms can attract spam; review submissions.
- For better media privacy, use a private bucket with signed URLs and server-side upload moderation; this requires additional backend code.
- The included browser UI currently records audio greetings and accepts text comments. Video upload/recording is not yet wired into the form.
- Use HTTPS hosting (GitHub Pages provides it) because browsers generally require a secure context for microphone access.
